# Sprint 04.1 and Sprint 05 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Polish the comparison API for a product client, then deliver and locally validate the first accessible support-operations decision journey across one Vercel Services project.

**Architecture:** Keep simulation, validation, statistics, and ranking in FastAPI. A narrow TypeScript mapper builds the existing `0.5.0` request from a canonical product template; a runtime-checked same-origin client renders backend evidence. Vercel Services routes `/api/simulation/**` to FastAPI and all other paths to Next.js.

**Tech Stack:** Python 3.12, FastAPI, Pydantic, SimPy, Next.js 16, React 19, TypeScript 5.9, Vitest, Testing Library, CSS, Vercel Services.

## Design self-review

The initial field-sheet direction risked resembling a generic editorial dashboard. The revision makes the workflow itself the signature: a continuous decision-trace rail connects incoming demand, four stages, and resolved/rework outcomes, while baseline/scenario evidence aligns to that same rail. Teal is reserved for active decisions; amber is reserved for constraints and failures. Metrics use quiet ruled rows rather than repeated cards.

## Plan self-review

- Covers every mandated API, template, product, deployment, test, browser, payload, documentation, and audit boundary.
- Preview success is conditional on real authentication and Services availability.
- No persistence, charting, component library, alternate API host, or production deployment is introduced.
- New behavior is test-first; configuration and documentation are validated immediately after creation.
